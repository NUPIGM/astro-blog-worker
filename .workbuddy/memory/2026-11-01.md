## 样式方案迁移：daisyUI → Starwind UI

**背景与关键判断**
- Starwind UI 不是 Tailwind 的替代品，而是构建在 Tailwind CSS v4 之上的组件层（其 `starwind.css` 入口即 `@import "tailwindcss"`，组件用 `tailwind-variants` 生成工具类）。因此「同时去掉 daisyUI 和 Tailwind」在技术上不成立。
- 与用户确认后定案：**保留 Tailwind v4 作为底层引擎 → 移除 daisyUI → 接入 Starwind 组件 + 语义 token**。
- Starwind 官方只提供 Astro / React 组件，**无 Svelte 适配**；`VideoList.svelte` / `VideoDetail.svelte` 按用户决定原样保留（且这两个组件当前未被任何页面引用）。

**实际排查结果**
- daisyUI 真实用法只有 3 个类，全在 `LoadingIndicator.astro`：`loading loading-spinner loading-lg`、`bg-base-100/70`、`text-base-content/70`。
- 其余 19 个 `.astro` 文件几乎全是纯 Tailwind 工具类（`text-gray-900`、`flex` 等）。
- `src/content/blog/03-tailwind-daisyui.md` 里的 daisyUI 类是**文章正文代码块**，属于内容而非样式，未改动。

**落地内容**
- `npx starwind init`（一键生成 `starwind.config.json`、`src/styles/starwind.css`，并给 tsconfig 加 `@/*` 别名）。
- 安装组件：button / badge / input / textarea / spinner / separator / prose（未用的 card / alert / skeleton 已删除，同步清理 config）。
- `src/styles/global.css` 改为 `@import "./starwind.css"` + 保留 `@tailwindcss/typography`（仅供 Svelte 岛继续用 `.prose`）+ 打印样式；移除 `@plugin "daisyui"`。
- 在 `starwind.css` 的 `@theme inline` / `:root` / `.dark` 中新增 `--brand` / `--brand-foreground`（red-500），承接首页 Logo 与页眉红色分隔线，保证视觉不偏移。
- 组件映射：daisyUI spinner → `Spinner`；`hr` → `Separator`；标签胶囊 → `Badge`；表单 → `Input`/`Textarea`/`Button`；正文排版 → `Prose`（替代 `.prose` + typography）。
- 颜色类统一收敛为 token：`gray-900→foreground`、`gray-500/600→muted-foreground`、`gray-200→border`、`gray-50→muted`、`blue-600→primary`、`red-500→brand`。

**踩坑记录**
1. `starwind init` 首次执行会被中断但已部分写入，二次执行提示 "already set up"——检查文件即可，不必重装。
2. 客户端 `<script>` 中不能引用 frontmatter 变量（`LoadingIndicator` 的 `SHOW_DELAY`），必须用字面量。
3. Starwind 生成的 `index.ts` 会 `import "./X.astro"`，纯 `tsc` 不认识；需在 `src/env.d.ts` 补 `declare module "*.astro"`，否则 `npm run check` 挂掉。
4. `@theme inline` 的变量不会以 `--color-*` 形式出现在产物里（会被内联进工具类）；lightningcss 还会合并同值选择器，所以按类名 grep 产物容易误判"样式丢失"，应查 `:root` 与规则体。

**验证**
- `astro build` 50 页通过；`tsc --noEmit` 无错误。

## 新增 404 页面

**文件**：`src/pages/404.astro`（构建产物 `dist/client/404.html`）

**设计取向**：沿用全站 A4 纸张式卡片语言——`BaseLayout` 居中大标题 + 红色 `Separator` + 克制留白。主视觉用 `bg-clip-text` 的红色渐变大号 404（`from-brand/30 to-brand/0`），消息文案偏口语（「这条链接通向一片空白」），不使用 emoji 或插画。

**结构**：错误提示 → 站内搜索 → 返回首页/全部博文双出口 → 推荐阅读（最新 3 篇）→ 四宫格快捷入口（标签/留言/关于/RSS，全部指向真实路由，无死链）。

**搜索实现（关键决策）**：静态站无后端，未引入第三方搜索服务。做法是构建期把 16 篇 blog 的 `title / description / tags / href` 序列化成 `JSON.stringify(...).replace(/</g,"\\u003c")`，以 `<script is:inline type="application/json" id="nf-index">` 内联进 404.html（约 5KB），客户端按空格分词做 AND 匹配，命中后 `createElement` 渲染结果（用 `textContent` 赋值，规避 XSS）。空查询回到初始态，`aria-live` 播报命中数，Esc 清空。

**兼容性处理**：脚本绑定用 `input.dataset.bound` 幂等守卫，并同时监听 `astro:page-load`（站内启用了 `ClientRouter`，软导航会换 DOM，模块脚本不重复执行）。

**顺带改动（小范围）**：`Seo.astro` / `BaseHead.astro` / `BaseLayout.astro` 增加可选 `noindex` 透传，404 输出 `<meta name="robots" content="noindex, nofollow">`。

**踩坑**：本机无 Chrome/Playwright，`qlmanage` 在本环境 sandbox 初始化失败，无法离屏截图；改为校验产物 CSS 里关键类是否真的生成（尤其 `bg-gradient-to-b` 与 `text-transparent` 同时存在，否则大号 404 会全隐形）。
- 产物中 daisyUI 残留 0；`bg-brand` / `text-foreground` / `border-border` 等 token 类均正常生成；Prose 样式拆到独立 chunk（272 条规则）。
- 结构零改动的证据：`git diff` 过滤掉颜色类后仅剩组件替换与格式调整，布局/栅格/间距类未变。
