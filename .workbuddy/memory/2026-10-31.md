## astro-blog-worker 代码审查与缺陷修复

**技术栈**：Astro 7 + @astrojs/cloudflare（assets 目录 dist/client）+ Tailwind4/daisyUI + Svelte5(legacy) + ClientRouter(SPA 过渡)

**修复的线上缺陷**
- `src/pages/rss.xml.js`：`link` 由 `/blog/${id}/` 改为 `/posts/${id}/`（此前所有订阅条目 404）
- `src/pages/data.json.ts`：只导出 POST 导致产物被写成 404 页面，改为 `GET: APIRoute` 并补 Content-Type / Cache-Control

**安全**

- 删除 `src/components/Seo.astro`（引用未定义的 structuredData/breadcrumbSchema，且硬编码他人站点信息）
- 删除未注册且缓存路径错误的 `public/sw.js`；`consts.ts` 移除 TURN_OFF_SW

**性能**
- 删除 `readFixture`（把整个 JSON 序列化→URL 编码→data: URL fetch→再 parse，三重拷贝），Svelte 组件直接用模块导入的对象
- `VideoDetail` 合并 onMount 与 `$:` 的重复请求，只保留响应式单点触发
- 删除 8 个无引用静态资源（logo2/avatar/bun_atc/ave/fav.ico/atkinson 字体），public 988K→588K
- 新增 `og-image.jpg`(1200x630, 35K) 替代 224K 的 logo.png 作为 og:image；新增 icon-192/512.png 供 manifest 使用
- 修 manifest.json：start_url `/index.html`→`/`，icon 指向不存在的 favicon.png→实有 png

**规范**

- tags/[tag] 标题此前误写为「留言」，改为「标签：xxx」+ 动态 description

## 依赖清理（import 实引分析 → package.json 校准）

扫描 src/（排除 content 下的示例代码）+ astro.config.ts，实际外部说明符仅 11 个包：
@astrojs/cloudflare、@astrojs/mdx、@astrojs/rss、@astrojs/sitemap、@astrojs/svelte、
@tailwindcss/typography、@tailwindcss/vite、astro、daisyui、svelte、tailwindcss。

改动：
- 删除 `@astrojs/starlight`（仅出现在 package.json/lock，config 与源码零引用，lock 中原有的 1 个 sitemap 嵌套副本一并清除）
- `lightningcss` 补入 devDependencies `^1.33.0`：astro.config 中 `cssMinify: "lightningcss"` 是隐式依赖，此前靠 vite@8.3.0 的嵌套副本(1.33.0)解析；提升后无嵌套副本，单版本

## 「astro dev 无法正常运行」排查

用户报 dev 起不来。实测结论：**项目代码本身无问题**，dev 能正常启动并提供服务。

定位到的三个真实原因（按影响排序）：
1. **端口 4321 被无关应用占用**：PID 59067（cwd `/Users/nupigm/WorkBuddy/档案系统`，首页 `<title>仪表盘</title>`）。`astro dev` 打印 `Port 4321 is in use, trying another one...` 后静默退到 4322，用户按习惯访问 4321 看到的是另一个应用 → 误判「博客跑不起来」。用户决定不改配置，沿用 4322。
2. **Vite 依赖预构建缓存被中断污染**：`node_modules/.vite/` 下残留 `deps_ssr_temp_1420e9e4`(13M/1583 项) 与 `deps_ssr_temp_bffca0cc`(12M/1561 项)。因锁文件在 20:22 刚变动，每次启动都 `Re-optimizing dependencies because lockfile has changed`；过程被 Ctrl+C 打断就留下 temp 目录，下次继续重优化。已移入 `~/.Trash`，冷启动 5585ms → 3301ms，`Re-optimizing` 与首次访问 `/rss.xml` 触发的 `program reload` 都消失。
3. **`about` 集合指向不存在的目录**：`src/content.config.ts` 定义 `about`（base `./src/content/about`）但目录不存在，每次启动刷 `[glob-loader] The base directory ... does not exist`；且每次 `Astro config changed` → `Clearing content store`。因 `about.astro` 是硬编码、全项目无 `getCollection("about")`，已删除该集合定义与 `collections` 中的注册。警告与 content store 清除均消失。

环境注记：在 WorkBuddy 内执行会注入 `NODE_OPTIONS=--require=...node-language-shim.cjs`，Vite 提交依赖缓存时 `fs.rm` 被 safe-delete 拦截（`SAFE_DELETE_BULK_CONFIRM_REQUIRED count:1561 threshold:50`）导致进程崩溃。属执行沙箱副作用，用户自身终端无此变量，**不是项目缺陷**；排查时需用 `env NODE_OPTIONS= npx astro dev` 绕开。

**遗留**：9229 inspector 端口被残留 workerd 占用，每次启动告警并改用 9230；需 `wrangler dev` 相关进程退出才消失。
**验证**：8 条路由（/、/posts/、/posts/first-post/、/about/、/tags/、/guestbook/、/rss.xml、/data.json）全部 200。
