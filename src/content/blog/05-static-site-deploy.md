# 把个人站点部署到 Cloudflare 和其他平台

写完博客内容后，下一步的关键动作就是“部署”。一个博客最重要的价值，是能让别人访问到，而不是只在本地运行。

## 为什么要部署到静态托管平台

静态站点天生适合部署到以下平台：

- Cloudflare Pages
- Vercel
- GitHub Pages
- Netlify

优点包括：

- 速度快
- 成本低
- 易于自动发布
- 适合博客和技术资料站点

## Astro 的静态输出

Astro 默认支持静态生成。执行构建命令：

```bash
npm run build
```

它会生成 `dist` 目录，里面就是最终可发布的静态文件。

## Cloudflare 部署方式

Cloudflare 适合想要更平滑的访问体验和更低的维护成本。如果你是纯静态站点，通常可以直接用 Pages 来部署：

1. 连接 GitHub 仓库
2. 选择自动构建
3. 设置构建命令：`npm run build`
4. 发布目录：`dist`
5. 配置域名和缓存

## 域名与自定义访问路径

部署之后，最常见的需求是：

- 自定义域名
- 绑定一级域名
- 配置 HTTPS
- 静态资源缓存优化

这些都是很常见，也是比较重要的站点细节。

## 发布后要注意的事项

部署完成后，不要忘记检查：

- 首页是否正常访问
- 文章详情页能否打开
- 图片资源是否加载正常
- RSS 页面是否可访问
- 路径是否正确显示

## 结语

站点从“代码能跑”到“能被访问”，这是从开发到上线的关键一步。很多人忽略部署环节，结果代码很好，但站点没有真正面向世界。用静态平台托管博客，是最稳妥、最适合内容站的做法之一。
